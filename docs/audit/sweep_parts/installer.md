## installer.md

This spec has changed most since the baseline. The integration branch now has real installers, from the release merge (74c2c8a) and the CI commit (0d77dc8). Windows has an Inno Setup `.exe` with a component picker, 5 languages, licence, space and version checks, HKLM keys, six file associations, the keep-or-remove user-data prompt and a portable zip. macOS has a productbuild `.pkg` in a `.dmg` with a picker, a universal build, notarisation and stapling when the secrets exist, and `Uninstall.command`. Linux has a reproducible `.tar.gz` with a manifest-driven user/system `install.sh`/`uninstall.sh`, and a `.deb` with desktop/MIME/icon integration and PGP signatures. `release.yml` publishes SHA-256 checksums and a GPG-signed manifest. The in-plugin side is now merged: the first-run tree and `.installed_version` (`InstallLayout`), the standalone opening files from the command line (`FileOpenRouter`), Download-to-Downloads, content packages, delta patches and the migration banner. The upgrade banner is still unwired (`InstallLayout::Result` is computed but unread) and `ContentPackage` has no GUI entry. Still missing: `.rpm`, the MSI wrapper, macOS Launch Services document types, a splash and a "What's new" link, the Docs component, and every automated install/upgrade/downgrade/signature test. Packaging rows count as "tested" only where CI builds the artifact (`build.yml` package job / `release.yml`); behaviour is otherwise verified only by the manual checklist in `docs/RELEASING.md` §6.
