# SPEC-SWEEP notes: state (state-model, file-formats, factory-content, error-recovery, docs/PRESET_FORMAT)

- [SM-46] A/B compare clears on a user-facing preset load (state-model 8.1) and posts "A/B cleared by preset load."; 8.1 is the specific intersection and wins over section 2's general "never touches ... A/B" list, which was edited to say so. `StateModel::loadingAPresetLeavesTheLayersAboveItAlone` inverted accordingly. Undo, A/B toggles, preset morph and the host session go through `fromVar`, not `loadPreset (File)`, and do not clear it.
- [SM-1/SM-16/FF-24..29] The processor's preset blocks (modulation, snapshots, midi_mappings, rhythm_engine, routing, character, tone_match) are written by `PresetManager::toVar` through a `capturePresetBlocks` hook and applied at the end of `fromVar`; the host session no longer writes them at the top level (they are inside its "preset" block) but still reads the old top-level keys for sessions saved before. Key spellings follow file-formats.md 2 where it names them; camelCase `midiMappings`/`rhythmEngine`/`toneMatch` are read as aliases.
- [SM-1/FF-24..29] A block a preset does not carry goes back to the module's as-built default (captured at construction), not the previous preset's state - except MIDI Learn mappings: `midi_mappings` is written only when non-empty and a preset without it keeps the current mappings, so a controller setup survives browsing factory presets (docs/PRESET_FORMAT.md's promise; live-performance 11 "per-preset by default but can be global"). A per-mapping "global" flag is not built.
- [PF-14] A parameter absent from `parameters` resets to its default on load, except `preset_morph_position`, `slide_guitar` and `slide_mode` (Slide Mode persists across a load, state-model 8.1).
- [ER-12/PF-11] A preset whose schema is newer than the build is refused with "X was made by a newer Luthier version. Update to open." (docs/spec-coverage.md C-20 resolution) rather than loaded and logged; docs/PRESET_FORMAT.md updated.
- [FF-2] Presets write `schema` beside `schemaVersion` and read `schema` first; a file with neither is schema 1. Other file types (setlist, pattern, kit, loop) not changed - deferred with FF-5.
- [FC-1] "Fuzz Face Lead" -> "Germanium Fuzz Lead" (old file retired by `FactoryPresets::writeAll`, name alias in `FactoryPresets::renamedPreset`, used by `indexOfPreset` and setlist entries); part "Modern LP Wiring" -> "Modern Single-Cut Wiring" (alias in `PartLibrary::renamedFactoryPart`, four factory guitars re-pointed). "Fuzz Face" and "LP Wiring" added to both trademark lists.
- [FF-29] No separate `midi_out_profile` name: the MIDI-out assignments, including the Luthier-profile SysEx switches, are `MidiOutConfig` inside the preset's `routing` block, which is what travels.
- [FF-20] `meta.modified`/`created` are stamped only when a file is saved (saveAs/saveCurrent/export), never in `toVar` itself, so the host state of an unchanged session stays byte-identical between two `getStateInformation` calls.
- [PF-7] `pruneOldBackups` only looked in `<root>/Backup`, but `backupBeforeOverwrite` files a replaced preset beside it (`<root>/<Category>/Backup/<date>`), so user backups were never pruned; the sweep now covers the category folders.
- [ER-19..21] `PresetManager::writeToFile` now takes the backup only after the new version is safely in the temp file, and checks the stream status before the rename (a full disk no longer renames a truncated file over the target).
- [ER-54] Switching to an empty B still switches (B starts as the current state, as before) and posts "B slot is empty; save current state to B first."; refusing the toggle would leave the header button out of step.
- [ER-38] The 30 s timeout covers both the global arm and a learn claimed from it (the user clicked a control and no CC came).
- [FC-22] Not tested: "Dreadnought", "Jumbo", "Parlor" and "Classical" guitars are single words, which breaks the section 12 `[Style Descriptor] [Family Word]` rule; renaming factory guitars is content work with migration aliases (left for FC-2's re-voice).
- [SM-47] Freeze and E-Bow clear on a load through their parameters (factory presets have them off; an absent key now resets to default), which is tested; no separate engine clear was added.
- [FF-5] Genre kit files use magic `luthier.genrekit` (file-formats.md 0.5 names none for kits); files without a marker are older ones and still load.
