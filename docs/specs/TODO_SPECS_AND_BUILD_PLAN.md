### 0.1 Premises in the request that the repo contradicts

1. **No `CLAUDE.md`/"obsolete-branches caveat" exists.** Only `claude.md` (a spec-coverage workflow, 29 lines). The only cron text is `docs/COORDINATOR_PLAN.md:265` (recurring coordinator check-in that restarts stalled workers on their old branch). The real obsolete-branch hazard is in S6.
2. **"Edition split largely exists" is true only for the catalogue** (guitars/amps/pedals/Jam/AA). The eight headline Pro features (Workshop, Tune Builder, Techniques, Tone Match, export, ranges, routing, deep realism) are **not gated at all** in the Free build today.
3. **Looper capacity mismatch.** `proLimits.looperSeconds = 600` but `Looper::kMaxLoopSeconds = 240` (`Looper.h:167`, clamped in `Looper::prepare`, `Looper.cpp:362`); LFO/follower limits are -1 (unlimited) but `ModSourceSlots::numLfos = 8`, `numFollowers = 2` (`ModMatrix.h:45,48`). Pro limits must be reconciled with reality before clamping (S7/E1).
4. **`LUTHIER_EDITION_NAME` is never defined** by CMake (`NormalizationCalibrator.cpp:264`), so a Free build reads and writes the same "standard" factory table and goldens as Pro, although Free plays substitute guitars (S9).
5. **Free macOS `auval` is hard-wired to Pro codes**: `ci_build.sh:243` runs `auval -strict -v aumu Lthr Ltha`, but the Free AU is `Lthf` (`cmake/Editions.cmake`). The Free macOS validate step will fail. Same in `docs/RELEASING.md:145`.
6. **PB-07 latency defect still present**: `EffectsChain::getLatencySamples()` counts only non-bypassed pedals (`EffectsChain.cpp:268-276`).

### S3. GUI combination audit of every control

- **Goal**: prove that every control works **in combination with the others**, not only alone: reachable, operable, audible, persistent, undoable, correct enable/visibility, in every context a user can create.
- **Current status**: the per-control half exists. `GuiReach` builds the real editor, walks 438 views x guitar contexts, operates 4870 controls (min/max/restore through attachments), checks 579 of 656 automatable params have a reachable control (10 intentionally hidden, 67 unused pedal-slot params). `Combo` (about 30 tests, `CombinationTests.cpp`, `ComboHarness.h` `Rig`/`Verdict`/`allPairs`) combines **parameters** pairwise and by seeded random but through the processor, not the GUI. Not covered: control interactions, enabled/visible state per context, "does it change the sound", the 4 technique pills the walk cannot operate (`bend_armed`, `scrape_armed`, `slap_armed`, `tap_armed`; audit finding 12).
- **Methodology** (new test group `GuiAudit`, files `Source/Tests/GuiAuditInventory.cpp`, `GuiAuditAudibility.cpp`, `GuiAuditContexts.cpp`, `GuiAuditPairs.cpp`; shared helpers added to `ComboHarness.h` only):

Commit the TSV as `Source/Tests/Golden/GuiInventory.tsv`; a test diffs the live inventory against it so a new/removed/renamed control fails until reviewed. Give the technique pill row a public toggle and an operator so the 4 unoperated pills are walked.
  2. **Contexts = pairwise covering array** (M): axes (about 12): guitar family (6-string, 7/8-string, bass 4/5, acoustic, custom), bridge type, playing mode (Mono/Poly/Chord), UI mode (Easy/Advanced), Slide on/off, Live mode, Jam on, Performance Assist on, ranges locked/unlocked, CPU quality (High/Auto/Low), edition (build-time), pedal rack full/empty. Generate with the existing `allPairs()` (use a fixed seeded `std::mt19937` and an explicit own shuffle, not `std::shuffle`, whose output differs across standard libraries; this is exactly why Linux never saw Windows row 48). About 40-60 contexts. In each: build editor, run the `GuiReach` operate pass, then assert the invariants in 4.
