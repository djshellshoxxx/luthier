# BUILD SPEC: "LUTHIER" — a physically-modeled realistic guitar synth VST

## Role
You are a senior audio DSP engineer specializing in physical modeling synthesis, and a working guitarist. Build a cross-platform VST3/AU plugin called **Luthier** using JUCE in C++. The plugin synthesizes a real guitar in every physical detail: body shape and wood, string material and gauge, pickup type and position, playing technique, room acoustics, and every micro-behavior of a real instrument, up to and including detuning, fretless play, and per-string articulation. Every note is generated by physical model, not sample playback. Deliver full source tree, CMake build, README, and preset bank.

## Guiding philosophy
Sample libraries fake the guitar by playing back recordings; they fall apart on articulations they weren't sampled for. Luthier models the physics, so every note reacts correctly to every technique: a bend into a slide into a vibrato into a harmonic works because the model knows what a string is. The plugin's job is to be indistinguishable from a real guitar in a mic'd room when played by a competent guitarist.

## Core engine architecture

### 1. String model (per string, up to 12 strings for 12-string mode)
Each string is an **extended digital waveguide** using bidirectional delay lines with per-string parameters:

- **Length** (scale length in mm, 610-660 mm typical, adjustable 500-750 mm for baritone/short-scale variants).
- **Tension** (Newtons, computed from target pitch, string mass, and length).
- **Linear mass density** (kg/m, derived from string gauge and material).
- **Young's modulus** (stiffness; determines inharmonicity).
- **Damping coefficient** (frequency-dependent; models string decay).
- **Nut position** (fret 0).
- **Bridge position** (fret 24+).
- **Current fretting position** (continuous 0.0 to 24.0; fractional values for fretless and bends).
- **Pluck position** (0.0 = at bridge, 1.0 = at nut; determines harmonic content).
- **Pluck strength** (0.0 to 1.0; velocity).
- **Pluck material** (pick / thumb / fingernail / thumbpick / brush; affects excitation spectrum).

**String excitation** uses a physically-derived impulse rather than pure noise:
- Pick excitation: short, bright, asymmetric impulse (2-4 ms) shaped by pick material and angle.
- Fingerstyle excitation: rounder, warmer impulse (5-8 ms) with less high-frequency content.
- Thumb excitation: even rounder, low-passed.
- Fingernail vs finger-pad: user-selectable, different spectra.

**Inharmonicity model**: real strings have partials that stretch above pure integer multiples. Model this with a per-string stiffness parameter that shifts partials according to `f_n = n*f_0 * sqrt(1 + B*n^2)` where B is the inharmonicity coefficient. Wound strings (low E, A) have higher B; plain strings (high B, E) have lower B.

**Sympathetic resonance**: every string couples to every other string through the bridge. When one string vibrates, other strings ring at frequencies matching their own partials. Implement as a coupling matrix (6x6 for a 6-string) with per-partial gain values derived from actual guitar measurements.

**String decay**: two-stage decay. Fast initial decay (first 200 ms) from high-frequency damping, then slow decay of the fundamental and low partials. Frequency-dependent lowpass in the feedback loop; cutoff drops over time.

**Sustain**: modeled as a target decay time per string. Steel strings sustain longer than nylon. Coated strings sustain longer than uncoated. The user can set sustain-per-string in Advanced mode.

### 2. Body model
The string signal is passed through a **body resonance model** that colors the sound with the physical resonance of the guitar body. Two implementation options, both provided, user-selectable:

**Option A: Commuted synthesis with impulse response**
- Each guitar body has a measured impulse response (IR).
- Convolve the string output with the body IR.
- Fast, accurate, but fixed to the sampled body.
- Ship a library of body IRs for every guitar type (see "Guitar types" below).

**Option B: Modal synthesis (resonant filter bank)**
- Each body modeled as a bank of 20-40 resonant filters at measured modal frequencies with per-mode Q and gain.
- Slower but responds dynamically to the model (a bigger virtual body actually rings bigger, not just louder).
- User can adjust body dimensions and the modes shift accordingly.

**Body parameters** (Advanced mode):
- Wood type (mahogany, maple, alder, ash, rosewood, spruce, cedar, koa) — each has a stored modal profile.
- Body size (small, medium, large, dreadnought, jumbo, parlor).
- Body depth.
- Top thickness.
- Bracing pattern (X-brace, fan-brace, ladder-brace for acoustics; solid-body / semi-hollow / hollow for electrics).
- Sound-hole size (acoustic only).
- Air resonance frequency (the "boominess" of the body; typically 100-140 Hz for acoustic, higher for smaller bodies).
- Age simulation (older wood has slightly reduced damping; adds openness).

### 3. Pickup model (electric and acoustic-electric)
Simulates the pickup transducing string vibration into an electrical signal.

Pickup types:
- **Single-coil** (bright, quack, hum-prone; Strat/Tele style).
- **Humbucker** (thicker, less bright, no hum; Les Paul/335 style).
- **P90** (between the two; grittier).
- **Piezo** (under-saddle transducer; percussive, bright, "acoustic-electric" character).
- **Magnetic soundhole pickup** (acoustic magnetic; darker, more electric-sounding).
- **Internal condenser mic** (for high-end acoustics; woody, air-y).
- **Blended piezo + mic** (with a balance knob).

Pickup parameters:
- **Position along string** (bridge, middle, neck; continuous, expressed as fraction of string length). Position determines which partials are emphasized (a pickup at 1/N of string length attenuates the Nth harmonic).
- **Coil count** (single or dual for humbucker).
- **Coil spacing** (for humbucker; affects hum cancellation and tonal character).
- **Coil resistance** (in kΩ; affects output level and treble roll-off).
- **Coil inductance** (in Henries; affects resonant peak of pickup).
- **Coil capacitance** (parasitic; affects high-frequency roll-off).
- **Magnet type** (Alnico 2, 3, 5, ceramic; each has a stored EQ curve).
- **Pole spacing** (affects string balance).
- **Height above strings** (closer = louder, more magnetic pull damping; farther = quieter, more sustain).

Pickup selector: user picks which pickup(s) are active (bridge only, neck only, middle only, bridge+middle, neck+middle, all three, etc., depending on guitar type). Blend knob for continuous mixing where applicable.

Coil-tap toggle for humbuckers (splits to single-coil).

### 4. Fretboard / fretting model
This is where playing technique lives.

**Fretted mode**:
- Notes snap to the nearest fret when played.
- 24 frets by default (adjustable 12-27 depending on guitar type).
- Fret positions calculated from equal-temperament (12-TET) by default; other temperaments selectable (just intonation, meantone, well-tempered, custom).
- Fret noise: brief transient click when fingers land on a fret (adjustable amount).
- Fret buzz: high-frequency rattle when fingering pressure is light or fret action is low (physical parameter).
- Fret action height (mm): affects buzz, note attack, and how easily bends catch.

**Fretless mode**:
- Notes are played at continuous positions on the fretboard.
- Pitch is exact based on continuous position; no quantization to semitones.
- Vibrato and slides feel more vocal (finger contact damps the string differently than a fret).
- No fret buzz.
- Slightly reduced sustain and different attack transient (finger flesh vs metal fret).
- Modeled by disabling the fret-quantization step and using continuous pitch values throughout the string model.

**Playing techniques** (each modeled physically, not sampled):

- **Bend**: continuous upward pitch change during a sustained note. Modeled as a slow increase in string tension. Bend amount in cents. Bend can be a half-step, whole-step, or user-defined. Multi-string bends (bending multiple strings simultaneously) supported.
- **Pre-bend**: bending the string before plucking; releasing after the pluck creates a downward pitch move.
- **Vibrato**: cyclic pitch modulation around a center pitch. Rate 3-8 Hz. Depth 5-50 cents. Modeled by cyclic tension modulation. Shapes: sine, triangle, "finger vibrato" (asymmetric), "classical vibrato" (small and fast), "blues vibrato" (wide and slow).
- **Slide (glissando)**: continuous pitch change from one note to another. Modeled by sliding the fretting position over time. Legato slide (no re-pluck) vs picked slide (pluck at start).
- **Hammer-on**: sounding a higher note without plucking, by fretting harder above the current note. Modeled by re-exciting the string with a light attack when the fretting position jumps upward.
- **Pull-off**: sounding a lower note without plucking, by pulling the finger off. Modeled by re-exciting with a lighter attack when position jumps downward.
- **Palm mute**: right-hand palm resting on the bridge; heavily damps strings and shortens sustain. Modeled by aggressive frequency-dependent lowpass and shortened feedback loop. Depth adjustable.
- **Natural harmonic**: touching the string at nodal points (12th, 7th, 5th frets) without fretting. Modeled by null-ing all partials except those at integer divisions of string length.
- **Pinch harmonic**: pick attack that hits both pick and thumb briefly, exciting a specific overtone. Modeled by re-excitation with a filtered impulse targeting specific harmonics.
- **Artificial harmonic**: fretting at one position, touching at a nodal point relative to that. Extends harmonic technique to any fretted note.
- **Tapping**: two-handed technique where fretting hand and picking hand both hammer/pull. Modeled as multiple simultaneous re-excitations.
- **Slide guitar (bottleneck)**: continuous pitch, no fret quantization even in fretted mode, sustained bright attack, some string noise from the slide moving. Toggleable regardless of guitar type.
- **Whammy bar / tremolo arm**: global pitch modulation of all strings simultaneously. Down-only for vintage trem, up-and-down for Floyd Rose / Steinberger TransTrem. Range in semitones adjustable. Dive-bomb capability (multi-octave drop). TransTrem mode maintains string intervals through the bend (chords stay in tune while bending).
- **String scrape / pick scrape**: dragging the pick along wound strings; produces a distinctive metallic scrape. Modeled with filtered noise excitation traveling along the string.
- **Muted picking**: light touch that damps strings without full palm mute. Different from palm mute.

### 5. Right-hand model
Simulates the picking/plucking hand.

- **Pick or fingers**: toggle per string or per note.
- **Pick material**: nylon, celluloid, delrin, metal, wood, felt. Each has a stored excitation spectrum.
- **Pick thickness**: thin (bright, snappy), medium, heavy (warm, rounded).
- **Pick angle**: parallel to strings (bright, aggressive) vs angled (softer, warmer).
- **Pick position**: distance from bridge in mm. Affects harmonic content; the same string plucked at different positions gives dramatically different tone.
- **Fingerstyle**: thumb, index, middle, ring, little. Each with its own excitation spectrum. Users can assign specific fingers to specific strings for realistic fingerpicking patterns.
- **Nail vs flesh**: for fingerstyle. Nail is brighter and sharper; flesh is warmer.
- **Strum direction**: down-strum (from low E toward high E) vs up-strum (reverse). Modeled as a short time delay between strings (2-15 ms depending on strum speed).
- **Strum speed**: how quickly the pick crosses the strings.

### 6. String noise and mechanical sounds
Real guitars produce non-pitched sounds that a good synth must include:

- **Finger slide noise**: squeak when fingers slide along wound strings. Volume proportional to slide speed. Higher on wound strings (E, A, D) than plain (G, B, E).
- **Pick attack transient**: brief click at pick contact.
- **Fret noise**: click when a finger lands on a fret.
- **String release noise**: soft thump when a note is released.
- **Body knock**: percussive tap on the body (for fingerstyle players who use it musically).
- **Pickup handling noise**: rare mechanical clicks from switching pickups mid-play (subtle).
- **Amp buzz** (electric only): 60 Hz hum for single-coils, absent for humbuckers. User-controllable amount.

All mechanical sounds have their own volume control (globally and per-type). Off by default in Easy Mode presets that want a "clean" sound; on for realism.

## Tuning system

- **Standard EADGBE** (default).
- Preset alternate tunings: Drop D, Drop C, Drop B, DADGAD, Open G, Open D, Open E, Open C, Half-step down (Eb Ab Db Gb Bb Eb), Full-step down (D G C F A D), Nashville tuning (paired octave strings).
- Custom per-string tuning (any note, any cent offset).
- **Detuning**: each string can be intentionally detuned in cents (-100 to +100). Perfect strings are never actually perfect on a real guitar; the plugin has a "realism detune" amount (0 to 20 cents) that randomizes each string slightly, refreshed on each preset load or user request.
- **Intonation error**: real guitars are slightly out of tune the higher up the neck you go. Model this with a per-string intonation offset that scales with fret position.
- **Fine tuner** knob per string in Advanced.

## Playing modes

The plugin accepts MIDI input and translates it into physical model actions. Three MIDI interpretation modes:

**1. Single-string / mono mode**
- Every note plays on a specific string (user-defined mapping or auto-selected based on pitch).
- Legato notes on the same string trigger hammer-ons, pull-offs, or slides depending on interval and velocity.
- Best for solo/lead lines.

**2. Polyphonic / chord mode**
- Chord voicings automatically assigned to strings using realistic fingerings.
- Chord detection engine identifies common chord shapes and voices them correctly.
- Strum simulation: incoming chord triggers a strum with configurable direction, speed, and dynamics.
- Best for rhythm/chord playing.

**3. Guitar controller mode**
- Direct string mapping: MIDI channel = string number (channel 1 = high E, channel 6 = low E), for use with hex pickup-based MIDI guitars like the Roland GK-3 or Fishman TriplePlay.
- Enables independent per-string bends, glides, and articulations.
- MPE (MIDI Polyphonic Expression) compatible for expressive controllers.

**Automatic technique detection**:
Based on incoming MIDI, the plugin infers technique:
- Fast note transitions on the same string → legato (hammer-on/pull-off).
- Pitch bend messages → string bend.
- Aftertouch → vibrato depth.
- Mod wheel → vibrato depth OR whammy bar (user-mapped).
- Sustain pedal → let all strings ring.
- Sostenuto pedal → hold selected notes only.
- Very high velocity + specific note → pinch harmonic (user-mappable).
- CC assignments for palm mute, pick position, slide activation, etc.

## Additional features

- **MIDI capture / retrospective record**: the plugin buffers the last 60 seconds of MIDI input; a "Save last take" button dumps it to a MIDI file.
- **Chord library**: a searchable panel of chord voicings the plugin will use in Chord mode. Users can edit fingerings.
- **Scale/mode display**: overlay on the fretboard view showing which frets are in the current key/scale. Doesn't affect audio, just visual aid.
- **Tab display**: shows played notes as guitar tablature in real time. Exportable.
- **Practice tools**: metronome, chord progression looper, backing track player.
- **Freeze / sustain infinite**: a toggle that holds the current note or chord indefinitely (like an E-Bow simulation).
- **Doubler**: automatic double-tracking of the guitar to a second panned copy with slight timing/pitch variation, for that classic wide guitar sound.
- **Feedback simulation**: when amp gain is high and note is sustained, feedback ramps up at a harmonic of the fundamental, gradually overtaking the fundamental. User-controllable threshold and speed.

## Randomization / humanization

Real guitarists are never machine-perfect. A "humanize" panel exposes:
- Timing jitter (ms).
- Velocity variation (%).
- Micro-detuning (cents, refreshed per note).
- Pick attack variation (%).
- Vibrato timing/depth variation (%).
- Occasional string noise / fret noise probability (%).

Each parameter has its own slider. At zero, output is machine-perfect. Cranked, output is loose and human. Default preset values are moderate.

## Identity constraints (the "always sounds like a guitar" rules)

Every generated sound must satisfy these to leave the engine:

1. **String physical validity**: string tension calculated from mass and pitch must be within realistic guitar range (30-90 Newtons per string typical). A tuning that would require impossibly high or low tension is rejected with a warning.
2. **Fret range validity**: notes must play at a valid fret position (0-24 or whatever the guitar type supports). Notes below the open-string pitch or above the highest fret are rejected or transposed.
3. **Body resonance always present**: the string signal is always convolved through some body model (even for electric, the body affects the sound). No "pure string" output unless user explicitly toggles "no body" as an experimental mode.
4. **Pickup always active (electric)**: at least one pickup must be selected. If user disables all pickups, plugin outputs silence and shows a small warning.
5. **Realistic response to velocity**: pick velocity affects pluck strength, which affects both loudness AND harmonic content (harder pluck is brighter). Not just a gain change.
6. **Realistic response to pitch**: higher notes decay faster than lower notes. Damping is frequency-dependent by design.
7. **Sympathetic resonance always active**: strings couple through the bridge. This gives guitars their characteristic "ring" and can't be disabled.
8. **String noise present when relevant**: finger slides always produce some noise on wound strings. Users can adjust the amount but zero is a specific stylistic choice, not a default.
9. **Chord voicings must be physically playable**: in Chord mode, the plugin refuses to voice a chord that would require humanly impossible fingering. It picks the closest playable voicing.

## Validator pipeline

Every note or phrase renders through:
1. String physics check: tension/pitch/mass consistency.
2. Fret validity check: note position within guitar's range.
3. Damping check: decay envelope realistic for note pitch.
4. Body coupling check: string signal is passing through body model.
5. Pickup output check: signal has expected spectral shape for pickup type.

Failures nudge parameters into range or reject the note with a diagnostic log entry.

## Threading and DSP correctness

- Audio thread: real-time only, no allocations, no locks, denormals disabled at top of processBlock, NaN guards on all recursive stages.
- String models: one per string, each with its own state, processed in parallel where possible.
- Body convolution: block-based with FFT convolution for efficiency (partitioned convolution for low latency).
- UI thread: all GUI updates.
- Worker threads: preset loading, IR loading, sympathetic coupling matrix recalculation on tuning change.

Sample-rate agnostic. Block-size agnostic. Handles sample-rate changes in `prepareToPlay`. All time-based effects and delay lines recomputed on rate change.

Parameter smoothing: 20 ms ramps on all continuous parameters. Filter coefficient recomputation cached and rate-limited.

## MIDI mapping / MPE support

- Standard MIDI CC support for all continuously-variable parameters.
- MPE support: per-note pitch bend, per-note pressure, per-note timbre (Y axis). Enables true polyphonic expression on MPE controllers (ROLI Seaboard, LinnStrument, Osmose).
- Pitch bend range configurable per string in Guitar Controller mode.
- Program change messages recall presets.

- Preset folders (add/remove).
- MIDI mapping global defaults.
- Export defaults.
- Performance: oversampling (2x/4x for amp stages), FFT block size for body convolution, max polyphony.
- Realism defaults: humanize amount, string age, intonation error.
- Appearance stub (deferred to user's theme system).

## Deliverables

1. Full JUCE project with CMake, Windows VST3 + macOS VST3/AU.
2. Source organized:
   - `/Source/DSP/String` (waveguide model per string)
   - `/Source/DSP/Body` (convolution + modal synthesis)
   - `/Source/DSP/Pickup` (electromagnetic pickup model)
   - `/Source/DSP/Amp` (amp head + cabinet + mic)
   - `/Source/DSP/Effects` (pedal/rack effects)
   - `/Source/DSP/Coupling` (sympathetic resonance matrix)
   - `/Source/Model/Guitar` (guitar type presets, string materials, body models)
   - `/Source/Model/Playing` (technique detection, chord voicing engine)
   - `/Source/UI/Easy`
   - `/Source/UI/Advanced`
   - `/Source/UI/Fretboard` (interactive fretboard component)
   - `/Source/Presets`
3. Body IR library (100+ IRs across guitar types, sizes, woods).
4. Speaker IR library (50+ IRs across cabinets, speakers, mic placements).
5. Documentation:
   - `README.md` (build steps, architecture)
   - `GUITAR_PHYSICS.md` (the math of the string, body, and pickup models)
   - `PLAYING_TECHNIQUES.md` (how each technique maps to model parameters)
   - `PRESET_FORMAT.md` (JSON schema)
   - `KEYBOARD_SHORTCUTS.md`
   - `USER_MANUAL.md`
   - `CHANGELOG.md`
   - `KNOWN_ISSUES.md`
   - `TROUBLESHOOTING.md`
6. Automated test suite:
   - Unit tests for each DSP module.
   - String tension calculation tests.
   - Chord voicing tests.
   - Pluginval level 10 in CI.
   - UI overlay dismissal tests.
   - Fuzz tests on all parameters (10,000 random states).
   - Latency reporting test.
7. Signed and notarized installers per platform.
8. CLI tool for offline batch rendering (render a MIDI file to WAV with a chosen preset).

## What makes this ship without a v1.0.1 hotfix

1. Every string physical model is stable at extreme parameter values (very low tension, very high pitch, aggressive bends).
2. Sympathetic coupling matrix never produces feedback runaway.
3. Body convolution latency is reported to the host correctly.
4. All 100+ body IRs load without clicks or discontinuities.
5. Chord voicing engine produces physically playable fingerings for every common chord.
6. Fretless mode produces genuinely continuous pitch, verified with a spectral analyzer sweep.
7. Bends and vibrato modulate string tension smoothly, not with zipper noise.
8. Pluginval level 10 passes cleanly on both platforms.
9. Overlay dismissal automated tests pass for every overlay type.
10. Tested in Ableton Live, FL Studio, Reaper, Studio One, Logic Pro, Cubase, Bitwig for 30 minutes each without stuck windows, focus bugs, or CPU spikes.
11. Tested with a real MIDI guitar controller (Roland GK, Fishman TriplePlay) and an MPE controller (ROLI, LinnStrument) end-to-end.
12. Recorded A/B comparison against real guitars in blind listening tests: 70%+ listeners can't reliably distinguish Luthier from a real guitar for typical playing.

Hit those and the first release will convince guitarists.
